# 토큰 운영 안내

> 테스트용 자료(FIXTURE) — 실제 프로젝트 안내가 아니다.

## 토큰 수명 주기

이 절은 액세스 토큰과 리프레시 토큰이 만들어지고 사라질 때까지의 흐름을 한곳에 모아 둔 긴 안내다. 길이를 일부러 늘려 조각 분할을 시험한다.

발급 단계에서는 로그인에 성공한 세션마다 액세스 토큰 하나와 리프레시 토큰 하나를 만든다. 액세스 토큰은 서명된 짧은 문자열이고 리프레시 토큰은 서버가 기록을 남기는 긴 문자열이다. 두 토큰은 같은 세션 식별자를 담는다.

저장 단계에서는 액세스 토큰을 메모리에만 두고, 리프레시 토큰은 보안 쿠키에 담는다. 브라우저 저장소에 토큰을 두지 않는 이유는 스크립트가 읽을 수 있기 때문이다. 서버는 리프레시 토큰의 해시만 저장한다.

갱신 단계에서는 리프레시 토큰 회전을 쓴다. 클라이언트가 리프레시 토큰으로 새 액세스 토큰을 받을 때마다 서버는 새 리프레시 토큰을 함께 내주고 이전 리프레시 토큰은 바로 무효로 만든다. 이미 무효가 된 리프레시 토큰이 다시 들어오면 재사용 공격으로 보고 그 세션의 모든 토큰을 폐기한다.

회전 규칙은 다음 순서로 확인한다:

1. 들어온 리프레시 토큰의 해시가 저장된 최신 해시와 같은지 본다.
2. 같으면 새 토큰 쌍을 발급하고 최신 해시를 바꾼다.
3. 다르면 재사용으로 보고 세션 전체를 폐기한다.

폐기 단계에서는 로그아웃, 비밀번호 변경, 관리자 강제 종료가 일어나면 해당 세션의 리프레시 토큰을 모두 지운다. 액세스 토큰은 만료 시각까지 남지만 짧게 잡아 위험을 줄인다. 폐기 목록은 따로 두지 않는다.

감사 단계에서는 발급, 회전, 재사용 감지, 폐기를 모두 감사 로그에 남긴다. 감사 로그에는 토큰 원문을 쓰지 않고 세션 식별자와 사건 종류, 시각만 쓴다. 로그 보관 기간은 90일이다.

여러 기기에서 같은 계정으로 로그인하면 기기마다 세션이 따로 생기고 토큰 쌍도 기기마다 따로 발급된다. 한 기기의 회전이나 폐기는 다른 기기의 세션에 영향을 주지 않는다. 다만 비밀번호 변경은 모든 기기의 세션을 함께 폐기한다.

시계 오차 때문에 막 만료된 액세스 토큰이 들어오는 일이 있다. 서버는 만료 시각 뒤 30초까지는 오차로 보고 받아들이지만, 리프레시 토큰에는 이 여유를 주지 않는다. 여유 시간은 설정으로 바꿀 수 있지만 1분을 넘기지 않는다.

토큰 서명 키는 90일마다 바꾼다. 키를 바꾼 뒤에도 이전 키로 서명된 액세스 토큰은 만료될 때까지 검증할 수 있도록 이전 공개 키를 한 주기 동안 함께 공개한다. 리프레시 토큰은 서버 기록과 대조하므로 키 교체의 영향을 받지 않는다.

장애로 토큰 저장소를 읽지 못하면 새 리프레시 토큰을 발급하지 않고 갱신 요청을 503으로 거절한다. 이때 이미 발급된 액세스 토큰은 만료될 때까지 계속 쓸 수 있다. 저장소가 복구되면 거절된 갱신은 클라이언트가 다시 시도한다.

관리자 강제 종료는 운영 도구에서 계정 단위로만 할 수 있다. 강제 종료를 하면 그 계정의 모든 세션과 리프레시 토큰을 지우고, 사유와 실행자를 감사 로그에 남긴다. 강제 종료된 계정은 다음 로그인 때 비밀번호를 다시 확인한다.

만료 시간은 액세스 토큰 10분, 리프레시 토큰 14일이다. 비밀번호 재설정 토큰은 이 안내가 아니라 인증 정책의 만료 규칙을 따른다.

## 토큰 오류 응답

토큰이 없거나 서명이 맞지 않으면 401을 돌려준다. 만료된 액세스 토큰도 401이며 클라이언트는 리프레시 토큰으로 갱신을 시도한다.
