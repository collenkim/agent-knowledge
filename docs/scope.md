# 책임과 초기 범위

## 이 저장소의 책임

- 등록된 원본 자료를 수집한다.
- 문서를 항목·절 단위로 나눈다.
- 출처·상태·버전을 관리한다.
- 검색 색인을 만들고 갱신한다.
- 키워드 검색을 수행하고, 후속 단계에서 벡터 검색과 결합할 경계를 둔다.
- 작업 범위에 맞는 근거를 반환한다.

## 맡지 않는 일

- 계획 수립, 프로젝트 배정, 실행 순서 조정
- 코드 생성, 작업 실행, 승인, 완료 판정
- 현재 단계·잠금·승인·재시도·체크포인트 저장. 이것은 각 에이전트의 실행 상태 저장소가 맡는다.
- 원본 저장소에 쓰기. 색인과 임시 파일은 언제나 원본 저장소 밖에 둔다.

결과는 수집한 자료인 근거다. 검증을 통과했다는 증거로 다루지 않는다.

## 자료 범위

- 프로젝트 내부 지식은 해당 프로젝트 저장소에 둔다.
- 공통 시스템 지도·용어·책임 구분만 이 저장소의 [knowledge/](../knowledge/README.md)에 둔다.
- 프로젝트 간 계약은 책임 원본 한 곳을 참조한다. 원본 문서를 여러 저장소에 복사하지 않는다.
- 실제 프로젝트 정책을 임의로 만들어 넣지 않는다. 동작 예제는 `evals/fixtures/`에 테스트용 자료로 표시해 둔다.

### 인터페이스·설정만 있는 부분

- `compose.yaml`은 Qdrant를 별도 프로세스로 띄우고 볼륨에 데이터를 저장하는 실행 구성이다. 코드는 Qdrant에 연결하지 않는다.
- `src/adapters/embedding.ts`의 `EmbeddingProvider`와 `src/adapters/vector-store.ts`의 `VectorStore`는 인터페이스다. 구현체가 없고 임베딩을 저장하는 테이블도 없다.
- `src/adapters/compatibility.ts`의 `checkEmbeddingCompatibility`는 제공자·모델 ID·모델 버전·차원·거리·분할 버전을 비교하는 순수 함수다. 색인이나 검색 경로에서 호출하지 않는다.
- `config/retrieval.yaml`의 `vector.enabled`는 `false`만 받는다. `true`로 두면 `config-invalid`(`vector-not-implemented`)로 실패한다.

벡터 검색 품질은 측정하지 않았다. 후속 작업은 [integration.md](integration.md#후속-작업)에 적는다.
